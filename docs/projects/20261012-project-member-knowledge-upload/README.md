## 已确认的需求

| 事项 | 结论 |
|---|---|
| 上传入口 | 现有 AI 平台，普通项目成员可以上传 |
| 入库方式 | 用户明确要求加入知识库后，由 Agent 调用 MCP 工具异步提交 |
| 生效方式 | 无需管理员内容审核，解析、索引和发布成功后自动生效 |
| 共享范围 | 同租户、同项目内共享；不做跨项目公共库 |
| 资料保留 | 新资料追加，全部旧资料保留；发布后新旧资料都可查询 |
| 重复资料 | 同项目、相同原件和处理配置：已可查则复用文档，处理中则复用任务；不重复解析或发起入库模型调用 |
| 耗时处理 | 文件完整上传并保存后返回任务号；解析和索引在后台，页面关闭/聊天 Stop 不停止已受理任务 |
| 成本目标 | 新增资料不批量重新解析、抽取或 Embedding 未变化的旧资料；全量重建不再作为默认上传方案 |
| 工业能力边界 | 做持久任务、幂等、隔离、失败恢复、配额与基本用量记录；不在平台复制一套知识库引擎 |
| 本轮工作 | G01、K01–K08 和 RAG 侧配置；遵守现有接口与回执，先验证后定稿候选构建 |

## 推荐的首版边界

复用现有聊天附件、项目权限、官方 MCP Adapter 和会话审批。RAG 侧新增 SQLite 持久任务、流式文件 hash、受管原件和处理成果保存，每次一个后台处理进程。项目可检索集合始终保留旧资料并追加新资料；“累计可检索”不等于“每次全量重建”。

G01已经验证并固定完整冻结的12项存储恢复到独立候选、新文档原生增量、flush/checksum/校验、原子激活路线。恢复和重复上传新增模型请求为0；失败候选不污染旧库。既有published不可变，读请求用可抛弃副本/lease，10次mock发布回收旧workspace内存与锁。选择与证据见 [plan.md 第8节](plan.md#8-增量处理发布和查询的技术门禁)；不建设全库重组、base＋delta、分布式队列。

首版必验 UTF-8 MD/TXT；PDF/DOCX/PPTX 在兼容 Linux、安装 documents extra 并逐格式验收后开放。能力接口如实报告支持列表。首版不增加独立 RAG 登录页面、内容审核流、目录树、删除/覆盖文档、Agent 完成后自动续跑或新的消息队列。
